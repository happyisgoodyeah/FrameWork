## 项目定位与技术基线

项目是在 ET9 Package 架构及状态同步示例上开发的二维网格拼图游戏。核心操作为选择关卡、拖拽拼图、网格吸附、按 90° 旋转、合法性判断和通关保存；YIUI 提供主菜单、选关、设置与存档界面。

## 程序集与分层

业务包内的 Scripts 子目录通过 AssemblyReference.asmref 归入 `ET.Model`、`ET.Hotfix`、`ET.ModelView`、`ET.HotfixView`。四个程序集定义位于 statesync/Runtime；各包的 packagegit.json 还会参与更新引用。仅查看 GamePlay.asmdef 或 GameBase.asmdef 会误判业务代码归属。

依赖关系为 Hotfix 引用 Model，ModelView 引用 Model，HotfixView 引用 Hotfix、ModelView 和 Model。Hotfix 不应直接读取 PuzzleView、GridView 或 Unity Transform；世界位置等信息由 HotfixView 转为 FloatVector2 传入逻辑层，或由逻辑层发布事件交给视图处理。

Entity 的 Child 与 Component 都有父子关系。PuzzleView 通过 Puzzle.GetComponent 获取，反向通过 GetParent<Puzzle> 获取。实体之间的持久引用使用 EntityRef；访问另一实体字段需声明 FriendOf。当前 gamebase/ModelView 下存在历史 Drag System，后续改动应结合实际程序集与现有约定，避免顺手搬迁造成广泛影响。

## 关键流程与源码入口

### 启动与存档准备

1. loader/Scripts/Loader/Client/Init.cs 初始化 World、日志、Fiber、资源包与代码加载器。
2. yiuistatesync/Scripts/HotfixView/Client/EntryEvent3_InitClient.cs 添加 GlobalComponent、ResourcesLoaderComponent、PlayerComponent、CurrentScenesComponent、SaveManagerComponent，并初始化 YIUI。
3. SaveManagerComponent.Awake 启动异步 Init；HotfixView 的 SaveManagerComponentLoadPath_SetPath 将 SaveDirectory 设为 Application.persistentDataPath，并设置版本。
4. 管理器尝试加载 `test/default` 存档，找不到时创建 GameSaveData。PlayerDataComponent 保存解锁、通关及成就列表。

### 选关与创建

主菜单的开始按钮打开 SelectLevelView；选关单元点击事件 LevelSlotComponentSystem 按 gridConfigId 创建 Grid，发布 AfterCreateGrid，再生成 Slot 和 Puzzle，随后打开 GameView。场景事件 EnterMapFinish_CreateGrid 还有固定创建 1001 的路径；调整入口时需确认是否产生重复网格。

Grid 保存槽位字典、拼图字典与边缘吸附集合；Puzzle 保存旋转、移动状态、初始位置、内部槽位及绑定列表；Slot 保存网格坐标、配置 ID 与 Puzzle 引用。SlotStateComponent 决定是否允许放置。

### 拖拽、吸附与旋转

gamebase 的 DragComponentSystem 使用输入及射线触发拖拽/点击事件。gameplay 的 HotfixView 事件和 PuzzleViewSystem 负责移动、触发器和动画；拖拽结束将世界位置传给 GridSystem.TryPlaceAndBindPuzzle，检查边界、占位及 Slot 可放置状态，再更新数据绑定和视图位置。

Click_PuzzleClick 对未放置拼图直接旋转，对已放置拼图先调用 TryRotatePlacedPuzzle。逻辑层先变更角度，合法时重新绑定，非法时回滚；视图层据结果播放旋转或摇晃。PuzzleSystem.GetOffsetByRotate 按 90° 倍数计算覆盖位置。

### 通关、返回与进度

SlotSystem.SetPuzzle 发布 SlotSetPuzzle。SlotSetPuzzle_CheckOver 调用 Grid.CheckGameOver；通关后调用 PassLevel(grid.Config().Id)、SaveAsync，打开选关界面并 Dispose Grid。选关界面 YIUIOpen 调用 Refresh，RefreshSlots 按玩家数据设置锁定和通关显示。旧 TODO 中这几项已有源码实现，但本次未运行验证。

### 存档格式

SaveManagerComponentSystem.SaveAsync 校验数据、更新时间、序列化并写文件，返回 SaveResult。开发环境走 MongoDB JSON（.json），发布版走 MemoryPack（.sav）；文件名为 `save_<PlayerId>_<SaveSlot>` 加对应扩展名。LoadAsync 查找文件、反序列化、检查头信息与数据，并恢复父子关系。

## 配置与生成内容

- 主要配置表在 yiuilubangen/Assets/Editor/Luban/Datas，包含 Grid、Puzzle、Slot、Audio、AI、Unit；定义在 Base，gameplay 也贡献 Base 定义。
- `ET/Excel/ExcelExporter` 当前由 yiuiluban/Editor/Window/LubanTools_Gen.cs 提供，聚合各包表定义并调用生成工具。
- 生成配置位于 yiuilubangen/CodeMode/Model 的 Client、Server、ClientServer 分支。修改应从表定义或生成器输入开始。
- UI 手写系统位于 gameplay/Scripts/HotfixView/Client/YIUISystem；生成绑定在 ModelView/HotfixView 下的 YIUIGen。Prefab 在 gameplay/Assets/GameRes/YIUI。
- 热更新、资源输出、根 csproj 和 asmref 均涉及工具生成；不要用修改生成结果替代修改真实来源。

## 已发现问题与待验证风险

以下是静态证据，除构建错误外未进行运行复现，不应写成已修复问题。

| 事项 | 源码证据与影响 | 计划 |
| --- | --- | --- |

| 保存失败仍继续收尾 | SlotSetPuzzle_CheckOver await SaveAsync 后未读取 SaveResult，随后跳转并释放 Grid | P03 |
| 通关事件与实体生命周期 | 每个槽位绑定都发布事件，无明显结算防重状态；await 后继续操作 Grid，需验证并发和存活 | P03 |
| 退出保存缺口 | 主菜单退出事件直接退出，Init.OnApplicationQuit 释放 World，SaveManager.Destroy 仅 Dispose 当前档案 | P04 |

| 坐标互转约定 | GridToWorldPosition 与 WorldToGridPosition 中 X/Y、宽高和轴方向混用，需用已知样本验证是否互逆 | P05 |
| 绑定列表重复添加 | GridSystem.BindPuzzleToSlots 调用 Slot.SetPuzzle 后再次添加 bindSlots，Slot.SetPuzzle 内本身也添加 | P05 |
| 选关边界与 ID 假设 | maxPage=Count/12+1，取配置使用 1000+序号；PassLevel 用 id+1 解锁且直接向通关列表追加 | P06 |
| 校验与文件头 | ComputeChecksum 返回空串；SaveSize/Checksum 在首次序列化之后设置；不能把现有代码视为已完成有效完整性保护 | P07 |
