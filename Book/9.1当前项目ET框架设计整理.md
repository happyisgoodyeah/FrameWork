# 当前项目 ET 框架设计整理

本文档基于当前仓库源码整理，重点描述本项目里 ET 框架的真实落点、启动链路、核心设计边界和业务扩展方式。它不是 ET 通用教程的替代，而是面向 `D:\unityproject\BehappyGame\Game` 当前工程的框架地图。

## 1. 项目整体定位

当前工程是 Unity + ET + YIUI + YooAssets + HybridCLR + Luban 的模板工程，并在模板之上加入了项目自己的基础层和玩法层。

- Unity 版本：`2022.3.62f3c1`
- 主入口场景：`Packages/cn.etetet.loader/Scenes/Init.unity`

- AOT metadata 目录：`Packages/cn.etetet.loader/Bundles/AotDlls`

## 3. Unity 到 ET 的启动链路

当前启动链路从 Unity `Init` MonoBehaviour 开始。

```text
Init.unity
  -> Init.Start()
  -> Init.StartAsync()
  -> 创建 Options / Logger / TimeInfo / FiberManager / ResourcesComponent / CodeLoader
  -> CodeLoader.Start()
  -> 加载 ET.Model / ET.ModelView / ET.Hotfix / ET.HotfixView
  -> 注册 CodeTypes
  -> 反射调用 ET.Entry.Start()
  -> Entry.StartAsync()
  -> 注册框架单例、消息映射、配置加载
  -> FiberManager.Create(Main, SceneType.Main)
  -> FiberInit_Main
  -> 根 SceneType 从 Main 切到 Options.SceneName
  -> 发布 EntryEvent1 / EntryEvent2 / EntryEvent3
```

### 3.1 Init 阶段

`Init.StartAsync()` 做 Unity 侧启动准备：

- `DontDestroyOnLoad(gameObject)`
- 注册未捕获异常日志
- 创建并注册 `Options`
- 从 `Resources/GlobalConfig` 覆盖 `Options.Instance.SceneName`
- 初始化 `Logger`
- 初始化 `TimeInfo`
- 初始化 `FiberManager`
- 通过 `ResourcesComponent` 创建 YooAssets 默认资源包 `DefaultPackage`
- 启动 `CodeLoader`

`Init.Update()` 和 `Init.LateUpdate()` 把 Unity 帧循环交给 ET：

```text
Update:
  TimeInfo.Instance.Update()
  FiberManager.Instance.Update()

LateUpdate:
  FiberManager.Instance.LateUpdate()
```

### 3.2 CodeLoader 阶段

`CodeLoader.Start()` 负责热更程序集加载。

编辑器下从 `Define.CodeDir` 读取：

- `ET.Model.dll.bytes`
- `ET.ModelView.dll.bytes`
- `ET.Hotfix.dll.bytes`
- `ET.HotfixView.dll.bytes`

非编辑器下通过 YooAssets 资源加载 DLL bytes。IL2CPP 下还会调用 HybridCLR：

```csharp
RuntimeApi.LoadMetadataForAOTAssembly(textAsset.bytes, HomologousImageMode.SuperSet);
```

程序集加载后注册：

```text
World.Instance.AddSingleton<CodeTypes, Assembly[]>(...)
```

之后反射调用：

```text
ET.Entry.Start()
```

### 3.3 Entry 阶段

`Entry.StartAsync()` 是 ET 运行时的框架初始化入口，主要做：

- 初始化时间精度
- 注册 Mongo BSON 类型
- 注册 MemoryPack 序列化
- 注册 Entity 序列化器
- 注册 `SceneTypeSingleton`
- 注册 `ObjectPool`
- 注册 `IdGenerater`
- 注册 `OpcodeType`
- 注册 `MessageQueue`
- 注册 `LogMsg`
- 调用 `CodeTypes.Instance.CodeProcess()`
- 加载 Luban 配置
- 创建主 Fiber

当前代码里 `NetServices` 初始化被注释，说明单机模式下从框架启动源头禁用了网络服务集合：

```csharp
//World.Instance.AddSingleton<NetServices>();
```

## 4. World、Singleton 与 CodeTypes

`World` 是全局单例容器，不是业务数据树。

它的职责：

- 管理 `ASingleton`
- 按类型保存单例实例
- 对实现 `ISingletonReverseDispose` 的单例记录反向释放顺序
- 在退出时统一释放

`CodeTypes` 是特性扫描中心。它在热更程序集加载后拿到所有类型，并记录带有 `BaseAttribute` 派生特性的类型。

典型消费者：

- `EventSystem` 扫描 `[Event]` 和 `[Invoke]`
- `EntitySystemSingleton` 扫描 `[EntitySystem]`
- `MessageDispatcher` 扫描 `[MessageHandler]`
- `OpcodeType` 扫描 `[Message]`
- `ConfigLoader` 扫描 `[Config]`

`CodeTypes.Instance.CodeProcess()` 会创建所有带 `[CodeProcess]` 的单例，例如：

- `EventSystem`
- `EntitySystemSingleton`
- `MessageDispatcher`

这也是 F7 热重载后需要重新构建扫描结果的原因。

## 5. Fiber 与 Scene

ET 的 Fiber 是调度边界，Scene 是 Fiber 根部的数据树节点。

`FiberManager` 支持三类调度器：

- `SchedulerType.Main`
- `SchedulerType.Thread`
- `SchedulerType.ThreadPool`

在 Unity 编辑器 View 模式或 WebGL 下，`Thread` 和 `ThreadPool` 会退回主线程调度。

创建 Fiber 的核心流程：

```text
FiberManager.Create(schedulerType, fiberId, zone, sceneType, name)
  -> new Fiber(...)
  -> 加入调度器
  -> 投递到该 Fiber 的 ThreadSynchronizationContext
  -> EventSystem.Invoke<FiberInit, ETTask>(sceneType, ...)
```

`Fiber` 内部包含：

- `Id`
- `Zone`
- `Root`：根 `Scene`
- `EntitySystem`
- `Mailboxes`
- `ThreadSynchronizationContext`
- `Log`

`Scene` 本身继承 `Entity`，同时实现 `IScene`。创建时会：

- 设置 `Id`
- 设置 `InstanceId`
- 设置 `SceneType`
- 持有 `Fiber`
- 把自身作为 `IScene`
- 注册到 EntitySystem

## 7. Entity 树设计

ET 的 `Entity` 是运行时数据树节点，不是 Unity `GameObject`，也不是扁平 ECS。

关系只有两类：

- Parent -> Child
- Entity -> Component

### 7.1 Child

Child 表示结构上的下级对象。

适合：

- 有独立 `Id`
- 同类型可存在多个
- 生命周期跟随父对象
- 是父对象组成结构的一部分

当前项目例子：

```text
Scene
  -> Grid
       -> Slot
       -> Puzzle
            -> Slot
```

对应声明：

```csharp
[ChildOf(typeof(Scene))]
public class Grid : Entity, IAwake<int, int>

[ChildOf(typeof(Grid))]
public class Puzzle : Entity, IAwake<int>

[ChildOf]
public class Slot : Entity, IAwake<int, int, SlotType>
```

### 7.2 Component

Component 表示挂在 Entity 上的能力、状态或表现扩展。

适合：

- 通过 `GetComponent<T>()` 按类型获取
- 同一实体通常只挂一个同类型组件
- 表示能力、表现、索引、管理器或桥接状态

当前项目例子：

```text
Grid
  -> GridView

Puzzle
  -> PuzzleView
  -> PuzzleDragComponent

Slot
  -> SlotView
  -> GridSlotStateComponent

Scene
  -> SaveManagerComponent
  -> CurrentScenesComponent
  -> ResourcesLoaderComponent
  -> YIUIMgrComponent
```

### 7.3 Entity 生命周期

Entity 创建和挂树时会自动触发生命周期系统。

常见流程：

```text
AddChild / AddComponent
  -> 设置 Id
  -> 设置 Parent 或 ComponentParent
  -> 继承 IScene
  -> 注册到 Fiber.EntitySystem
  -> EntitySystemSingleton.Awake(...)
```

释放流程：

```text
Dispose()
  -> 取消注册
  -> 递归释放 Children
  -> 递归释放 Components
  -> 触发 Destroy System
  -> 从父节点移除
  -> 回收到 ObjectPool
```

跨 `await` 后 Entity 可能已释放，所以异步表现逻辑里常见检查：

```csharp
if (scene.IsDisposed || grid.IsDisposed)
{
    return;
}
```

## 8. EntitySystem 机制

ET 把数据和逻辑拆开：

- Entity 类优先只放字段
- 逻辑放静态 partial System
- 生命周期通过接口和特性连接

典型写法：

```csharp
[EntitySystemOf(typeof(Grid))]
public static partial class GridSystem
{
    [EntitySystem]
    private static void Awake(this Grid self, int width, int height)
    {
    }
}
```

`EntitySystemSingleton` 在启动时扫描所有 `[EntitySystem]`，建立：

```text
Entity Type -> System Type -> SystemObject list
```

支持的典型系统：

- `IAwakeSystem`
- `IDestroySystem`
- `ISerializeSystem`
- `IDeserializeSystem`
- `IGetComponentSysSystem`
- `AClassEventSystem<T>`，用于 `IUpdate` / `ILateUpdate` 等类事件

`Fiber.EntitySystem.Publish(new UpdateEvent())` 会驱动实现 `IUpdate` 的实体更新。

## 9. EventSystem 与 Invoke

`EventSystem` 负责两类分发：

- `Publish / PublishAsync`
- `Invoke`

### 9.1 Publish

Publish 是广播语义。

特点：

- 可以没有订阅者
- 适合模块间通知
- 通过 `SceneType` 过滤
- `PublishAsync` 会等待所有匹配 handler

典型写法：

```csharp
[Event(SceneType.Current)]
public class AfterCreateGrid_CreateGridView : AEvent<Scene, AfterCreateGrid>
{
    protected override async ETTask Run(Scene scene, AfterCreateGrid args)
    {
    }
}
```

当前项目 PuzzleCore 使用数据创建事件驱动表现创建：

```text
Create Grid 数据
  -> PublishAsync AfterCreateGrid
  -> HotfixView 创建 GridView

Create Puzzle 数据
  -> PublishAsync AfterCreatePuzzle
  -> HotfixView 创建 PuzzleView

Create Slot 数据
  -> Publish AfterCreateSlot
  -> HotfixView 创建 SlotView
```

这种设计让 Hotfix 数据层不直接依赖 HotfixView 表现层。

### 9.2 Invoke

Invoke 是强约束调用。

特点：

- 必须有目标 handler
- 没有 handler 会抛异常
- 适合框架内部强约束边界
- 不适合替代普通函数调用

当前项目典型用途：

- `FiberInit` 按 SceneType 初始化 Fiber
- `ConfigLoader` 按 ConfigType 获取/反序列化配置
- `MailBoxComponent` 按 MailBoxType 分发消息
- YIUI 通过 `EYIUIInvokeType` 接入资源加载、实例化、释放等操作

## 10. SceneType 设计

`SceneType` 是 partial 静态类，由多个包扩展。

核心包：

```csharp
public const int All = 0;
public const int Main = PackageType.Core * 1000 + 1;
public const int NetInner = PackageType.Core * 1000 + 2;
public const int NetClient = PackageType.Core * 1000 + 3;
```

状态同步包：

```csharp
public const int StateSync = PackageType.StateSync * 1000 + 20;
public const int Current = PackageType.StateSync * 1000 + 21;
```

`SceneTypeSingleton` 建立 int 和名字的双向映射，并提供 `IsSame`：

```text
相等 -> true
任意一方为 All(0) -> true
其他 -> false
```

这使事件可以绑定到：

- 全局：`SceneType.All`
- 根业务场景：`SceneType.StateSync`
- 当前游戏场景：`SceneType.Current`
- 服务端场景：`SceneType.Gate` / `SceneType.Map` 等

## 11. 配置系统与 Luban

当前项目使用 Luban 生成配置代码和二进制配置。

入口：

```text
Packages/cn.etetet.yiuiluban/Scripts/Model/Share/Config/LubanConfigLoader.cs
```

加载流程：

```text
Entry.StartAsync()
  -> ConfigLoader.LoadAsync()
  -> Invoke<LubanGetAllConfigBytes>
  -> 根据 [Config] 类型收集 bytes
  -> Invoke<ConfigDeserialize>
  -> 反序列化成配置 Category
  -> 注册为 World Singleton
  -> ResolveRef
  -> ILubanConfigSystem 初始化
  -> ConfigProcess 单例初始化
```

客户端 bytes 来源：

```text
Packages/cn.etetet.yiuilubangen/Scripts/HotfixView/Client/LubanClientLoaderInvoker.cs
```

编辑器下按 `GlobalConfig.CodeMode` 读取：

```text
Packages/cn.etetet.yiuilubangen/Assets/LubanGen/Config/Binary/{CodeMode}/{ConfigName}.bytes
```

StartConfig 读取：

```text
Packages/cn.etetet.yiuilubangen/Assets/LubanGen/StartConfig/{Options.StartConfig}/Binary/Server/{ConfigName}.bytes
```

运行时非编辑器下通过 `ResourcesComponent` 加载 TextAsset。

设计边界：

- `ConfigLoader` 只定义加载流程
- 具体 bytes 来源由 Invoke handler 实现
- 反序列化方式由 ConfigType 对应 handler 实现
- 业务读取配置应通过生成的 Category 单例或业务 helper

## 12. YooAssets 与资源生命周期

`ResourcesComponent` 在 Fiber 创建前初始化，用于加载 DLL、配置、AOT metadata 等启动期资源。

业务期资源使用：

```text
ResourcesLoaderComponent
```

位置：

```text
Packages/cn.etetet.yooassets/Scripts/ModelView/Client/ResourcesLoaderComponent.cs
```

它是 Entity Component，生命周期跟随 Parent。比如挂在 CurrentScene 上时，CurrentScene 释放后资源句柄也随之释放。

当前项目根 Scene 启动时会添加一个 `ResourcesLoaderComponent`；CurrentScene 创建时也会按场景需要添加资源加载器。

设计建议：

- 启动期资源用 `ResourcesComponent`
- 业务运行时资源用 `ResourcesLoaderComponent`
- 当前场景资源挂在当前场景上
- 不要把玩法资源加载散落到无生命周期管理的静态缓存里

## 14. 网络、Actor 与当前单机状态

框架仍保留完整网络和 Actor 能力，但当前启动配置已将服务端网络路径禁用。

### 14.1 网络基础

核心类型：

- `NetComponent`
- `Session`
- `AService`
- `KService`
- `OpcodeType`
- `MessageSerializeHelper`

`NetComponent` 负责：

- 创建 KCP Service
- 处理 Accept
- 处理 Read
- 处理 Error
- 在 Update 中驱动 Service

收到网络消息后：

```text
OnRead
  -> MessageSerializeHelper.ToMessage
  -> EventSystem.Invoke(sceneType, NetComponentOnRead)
```

### 14.2 Actor 消息

挂了 `MailBoxComponent` 的 Entity 就是 Actor。

核心流程：

```text
ProcessInnerSender.Send / Call
  -> MessageQueue
  -> 目标 Fiber 的 ProcessInnerSender.Update
  -> Fiber.Mailboxes.Get(instanceId)
  -> MailBoxComponent.Add
  -> Invoke(MailBoxType)
  -> MessageDispatcher.Handle
  -> MessageHandler.Run
```

当前基础入口 `EntryEvent1_InitShare` 会给根 Scene 添加：

```text
MailBoxComponent
ProcessInnerSender
```

因此即使当前是单机，进程内 Actor 消息队列能力仍在。

### 14.3 当前禁用点

当前项目至少有两处明确单机化：

- `Entry.StartAsync()` 未注册 `NetServices`
- `EntryEvent2_InitServer` 注释了 NetInner、Realm、Gate、Map 等 Fiber 创建

如果后续恢复联网或服务端模式，需要从这两个启动边界开始审查，再检查 `GlobalConfig.CodeMode`、StartConfig、网络地址和相关 SceneType handler。

## 15. 序列化与数据恢复

ET 同时使用 Mongo BSON 思路和 MemoryPack。

Entity 中常见标记：

- `[BsonIgnore]`
- `[BsonElement]`
- `[BsonIgnoreIfNull]`
- `[MemoryPackIgnore]`
- `[MemoryPackInclude]`

Entity 反序列化后通过 `IScene` 设置和 `BeginInit()` 恢复关系：

- 恢复 component parent
- 恢复 child parent
- 恢复 IScene
- 触发 Deserialize System
- 对实现 `ISerializeToEntity` 或 `IsSerilizeWithParent` 的节点执行 Serialize System

当前项目存档系统落在 `gamebase`：

```text
SaveManagerComponent
SaveIndexComponent
SaveSlot
SaveDataRoot
SaveDataHeaderComponent
SaveValidationDispatcherComponent
```

玩法扩展数据落在 `gameplay`：

```text
LevelProgressSaveDataComponent
PuzzleArchiveSaveDataComponent
```

## 16. 当前 PuzzleCore 业务设计样例

PuzzleCore 是当前项目很好的 ET 分层样例。

### 16.1 数据层

位置：

```text
Packages/cn.etetet.gameplay/Scripts/Model/Client/PuzzleCore
```

核心实体：

```text
Grid
Puzzle
Slot
GridSlotStateComponent
```

结构：

```text
Scene
  -> Grid
       -> Slot
       -> Puzzle
            -> Slot
```

Grid 持有棋盘尺寸、配置 id、可放置数量、占用数量和完成事件状态。Puzzle 持有拼图配置、初始位置、旋转等运行时数据。Slot 既可表示棋盘格，也可表示 Puzzle 形状格，具体语义由父节点和 SlotType 决定。

### 16.2 逻辑层

位置：

```text
Packages/cn.etetet.gameplay/Scripts/Hotfix/Client/PuzzleCore
```

核心系统：

- `GridSystem`
- `PuzzleSystem`
- `SlotSystem`
- `GridSlotStateComponentSystem`
- `PuzzleBootstrapHelper`
- `PuzzlePlacementHelper`
- `PuzzleLevelRuntimeHelper`

数据创建流程：

```text
PuzzleBootstrapHelper.CreateGridAsync
  -> 读取 GridConfig
  -> 创建 Grid
  -> PublishAsync AfterCreateGrid
  -> 创建 Grid Slot
  -> 创建 Puzzle
  -> PublishAsync AfterCreatePuzzle
  -> 发布 Puzzle 下 Slot 的 AfterCreateSlot
  -> 刷新 Grid 统计
```

配置异常会直接抛出，符合当前项目“尽早暴露产生原因，不靠大量兜底掩盖状态问题”的规则。

### 16.3 表现层

位置：

```text
Packages/cn.etetet.gameplay/Scripts/ModelView/Client/PuzzleCore
Packages/cn.etetet.gameplay/Scripts/HotfixView/Client/PuzzleCore
```

核心表现组件：

```text
GridView
PuzzleView
SlotView
PuzzleSceneRoot
PuzzleDragComponent
```

表现创建由事件驱动：

```text
AfterCreateGrid -> GridView
AfterCreatePuzzle -> PuzzleView
AfterCreateSlot -> SlotView
```

表现层会显式检查 Unity 场景和资源加载条件：

```text
Scene.IsPuzzleViewReady()
  -> ET Scene 未释放
  -> 能解析同名 Unity Scene
  -> 存在 ResourcesLoaderComponent
```

`PuzzleSceneRoot` 负责把 ET Scene 映射到 Unity Scene，并查找 Unity 根节点：

```text
SceneRoot
  -> GridRoot
```

这避免了把 ET `Scene` 当 Unity `Scene` 使用。

## 17. 开发边界和推荐实践

### 17.1 新业务放置位置

可复用基础能力：

```text
Packages/cn.etetet.gamebase
```

当前项目专属玩法和 UI：

```text
Packages/cn.etetet.gameplay
```

模板或示例扩展：

```text
Packages/cn.etetet.yiuistatesync
Packages/cn.etetet.statesync
```

不要把主要业务放进 `Assets/Scripts`。

### 17.2 分层调用方向

推荐方向：

```text
Model -> 只放数据定义
ModelView -> Unity 桥接和表现数据
Hotfix -> 业务逻辑，不调用 HotfixView
HotfixView -> 表现逻辑，可依赖 Hotfix
```

数据层驱动表现层的推荐边界：

```text
数据创建完成
  -> 发布事件
  -> HotfixView 订阅并创建表现
```

不要让 Hotfix 直接创建 Unity GameObject。

### 17.3 Entity 设计判断

设计新对象时先判断：

- 它是不是父对象结构的一部分
- 它是否需要同类型多个实例
- 它是否只是挂在实体上的能力或状态
- 它的生命周期是否跟父节点一致

通常：

- 多个结构子对象用 Child
- 单个能力/表现用 Component
- 稳定通用字段放 Entity 本体
- 可插拔能力拆 Component

### 17.4 事件拆分边界

适合 Publish 的情况：

- 模块间广播
- 生命周期事件
- 数据层通知表现层
- 允许没有订阅者

适合 Invoke 的情况：

- 必须有处理者
- 框架边界分发
- 按 SceneType、ConfigType、MailBoxType 选择唯一职责处理

不建议为了“解耦”把同一个初始化阶段拆成大量小事件。若属于同一模块、同一阶段、顺序强相关，优先放在一个清晰 handler 内组织。

### 17.5 异步和生命周期

ET 默认是事件驱动 + 单线程异步，`await` 不代表多线程。

长链异步要注意：

- Entity 跨 await 后可能已释放
- 场景可能已切换
- 资源加载回调回来时表现可能已创建或销毁

表现层加载后应检查关键对象状态。

### 17.6 状态正确性

当前项目更推荐从数据创建、状态流转和调用边界保证状态正确。

优先：

- 创建时校验配置一致性
- 重复创建直接暴露异常
- 缺失必要状态时记录错误或抛出
- 状态切换集中在 System/Helper 的明确入口

谨慎：

- 静默补齐缺失状态
- 自动修复异常状态
- 在表现层大量兜底掩盖数据层问题

## 18. 常见排查路径

### 18.1 启动失败

检查顺序：

1. 是否从 `Packages/cn.etetet.loader/Scenes/Init.unity` 启动
2. 是否执行过 `F6`
3. `Packages/cn.etetet.loader/Bundles/Code` 下 DLL bytes 是否更新
4. `GlobalConfig.asset` 中 `SceneName` 是否存在于 `SceneType`
5. `GlobalConfig.asset` 中 `CodeMode` 是否符合当前运行目标
6. `EntryEvent1/2/3` 对应 SceneType 是否匹配

### 18.2 代码改了但还是旧逻辑

检查顺序：

1. 执行 `ET/Loader/Compile` 或 F6
2. 检查 `Bundles/Code` 下 DLL bytes 修改时间
3. Play 模式中仅 Hotfix/HotfixView 改动可尝试 F7
4. 如果改了 Model/ModelView，通常要重新 F6 并重启 Play
5. 如果改了配置或生成代码，执行对应生成流程

### 18.3 UI 不显示

检查顺序：

1. `EntryEvent3_InitClient` 是否执行
2. `YIUIMgrComponent.Initialize()` 是否返回 true
3. `YIUIRoot` 是否加载成功
4. YIUI 绑定和 prefab 是否重新生成
5. UI 事件绑定的 SceneType 是否正确
6. `AppStartInitFinish` 后是否有页面创建事件

### 18.4 Puzzle 表现不显示

检查顺序：

1. Grid/Puzzle/Slot 数据是否创建成功
2. 是否发布 `AfterCreateGrid` / `AfterCreatePuzzle` / `AfterCreateSlot`
3. 对应事件是否运行在 `SceneType.Current`
4. `Scene.IsPuzzleViewReady()` 是否为 true
5. Unity 场景名是否和 ET Scene 名称对应
6. Unity 场景下是否有 `SceneRoot/GridRoot`
7. 当前 Scene 是否有 `ResourcesLoaderComponent`
8. 配表 prefab path 是否能通过 `ResourceLocationHelper.ToAssetLocation` 找到资源

### 18.5 配置不生效

检查顺序：

1. 是否执行 `ET/Excel/ExcelExporter`
2. `LubanGen/Config/Binary/{CodeMode}` 是否生成新 bytes
3. 当前 `GlobalConfig.CodeMode` 是否和读取目录一致
4. StartConfig 是否正确
5. 配置 Category 是否被 `ConfigLoader.LoadAsync()` 注册
6. 业务 helper 是否读取了正确配置 id

### 18.6 网络或服务端逻辑不运行

当前项目默认单机化，先确认是否需要恢复服务端启动。

检查点：

1. `Entry.StartAsync()` 中 `NetServices` 是否仍注释
2. `EntryEvent2_InitServer` 中 Fiber 创建逻辑是否仍注释
3. `GlobalConfig.CodeMode` 是否为服务端或 ClientServer
4. StartConfig 是否包含对应进程和场景
5. SceneType handler 是否存在
6. NetComponent 是否创建

## 20. 一句话总结

当前项目的 ET 框架以 `World` 管全局单例、`CodeTypes` 管热更类型扫描、`Fiber` 管调度边界、`Scene/Entity` 管运行时数据树、`EventSystem` 管模块协作、`EntitySystem` 管生命周期逻辑。当前运行形态偏单机客户端：服务端网络 Fiber 启动被禁用，业务主要在 `StateSync` 根场景下初始化，再通过 `Current` 场景承载玩法数据和 Unity 表现。
